# 구매요청서 결과 양식

이 양식은 필요한 사용자 답변을 받은 뒤 작성하는 ERP 복사용 초안이다. 미답변 필수 정보가 있으면 먼저 짧게 질문하고 답변을 기다린다. 사용자가 보완용 초안을 원한 경우에만 누락 값을 `[확인 필요: 항목]`으로 표시한다. 별도 파일이 요청되지 않으면 대화에 표시한다. 요청서가 여러 건이면 건별로 아래 내용을 반복한다. 해당하지 않는 선택 항목은 생략한다.

## 상태와 확인 사항

- 상태: `보완 필요 초안` 또는 `입력 가능한 초안`
- 실제 ERP 작업 상태(해당 시): `미입력 / 일부 입력·미저장 / 입력 완료·미저장 / 저장됨(PRQ) / 상신됨`. 입력 확정된 품목 `n/N개`, 부가정보 비고 네 항목의 반영 여부, 남은 입력을 함께 기록한다. 초안 내용과 실제 화면 반영을 구분한다.
- 적용 기준: 사내 OmniEsol 구매요청 안내 v1.2 / 2026-09-30
- 요청자 확인: 실제 소속 부서·팀·파트 / 성명 / 직급 / 직책(있으면). 직급·직책은 확인 정보이며 ERP에 없는 입력란을 만들지 않는다.
- 요청서 묶음 근거: ERP 거래처 및 분리/통합 이유
- 확인할 내용: 실제 입력·첨부 전에 필요한 미확정 항목
- 상신까지 요청받은 경우: 사전에 확인한 결재 순서와 이름·직급·직책·소속, 메일 알림·공개 범위

## 기본정보

| ERP 항목 | 입력값 |
|---|---|
| 공장 | 실제 공장 확인값 |
| 요청일 | 실제 요청일 |
| 요청자 | 실제 요청자 |
| 구매그룹 | 요청부서 팀/파트 |
| 구매조직 | Default 구매조직 |
| 요청유형 | 구매요청 |
| 부가세포함여부 | 결제방식에 따른 부가세 별도/포함 |
| 통화 | 견적 통화 |
| 거래처 | 등록 거래처 또는 기타거래처 |
| 저장위치 | 실제 납품받는 동 |
| 납기예정일 | 확정 요청 납기 |
| MRS 번호 | 실제 발급 PRQ 또는 발급 전 |

구매유형 등 안내문이 고정값으로 지시하지 않은 항목은 실제 ERP 기준을 확인한 경우에만 추가한다. 계정범주는 아래 품목별 분류와 일치시킨다.

## 품목별 입력표

| No. | 계정범주 | 품목코드·품목명 | 모델·규격·옵션(행 비고) | 수량 | 단위 | 입력 단가 | 입력 금액 | 거래처 | 저장위치 | 납기 |
|---|---|---|---|---:|---|---:|---:|---|---|---|
| 각 품목 | 실제 분류 | 확인값 또는 확인 필요 | 제품 식별 정보 | 실제 수량 | 확인 단위 | 계산값 | 계산값 | 확인값 | 확인값 | 확인값 |

금액 기준을 표 바로 위에 적는다: `공급가액/VAT 별도` 또는 `VAT 포함/배송비 포함 최종결제금액`. 품목 수량×단가와 합계, 원래 견적/장바구니 합계, 배송·운임·할인의 반영 위치를 대조한다. ERP가 허용하는 소수점이나 반올림을 모르면 확인 사항에 남긴다. 외화는 해당 통화 표시를 유지한다.

자산이 있으면 별도 표를 추가한다.

| 자산 품목 No. | 예산단위 | 예산계정 | 확인 근거 |
|---|---|---|---|
| 각 자산 품목 | 실제 연도 ERP 값 | 해당 센터 실제 항목 | 사용자/ERP 확인 또는 확인 필요 |

## 부가정보 탭 비고에 붙여 넣을 내용

아래 네 줄의 번호·제목과 실제 내용을 모두 유지한다. 품목 행 비고와 별도로 ERP **부가정보 탭 비고**에 입력한다. 빈칸·미확정 값이 있으면 실제 저장·상신을 진행하지 않는다.

```text
1) 구매목적: 받은 사실로 작성
2) 사용장소: 실제 동·층·시험실
3) 관리부서: 실제 팀/파트
4) 상세내용: 모델·규격, 구매 수량과 근거, 교체/증설 사유, 납기 필요성 등 확인된 사실
```

## 그룹웨어 첨부자료 및 파일명 계획

아래 파일은 그룹웨어 결재창에만 등록한다. ERP에는 첨부하지 않는다.

스크린샷 대체가 허용되는 인터넷 소모품은 장바구니 캡처를 우선 계획한다. 같은 판매처의 여러 품목은 옵션·수량·가격·합계가 읽히는 한 장으로 묶고, 불가능하거나 정보가 빠지면 필요한 캡처만 보완한다. 자료종류는 `장바구니`, 요청품목은 실제 품목명 또는 `품목N종`으로 적는다. 상품·고정자산의 필수 견적서는 별도로 유지한다.

| 자료종류 | 상태/확인할 내용 | 파일명 계획 |
|---|---|---|
| 분류별 필요 자료 | 파일 확인 완료 / 사용자 제공 예정 / 미제공·확인 필요 | 실제PRQ_자료종류_요청품목(거래처명).원래확장자 |

PRQ가 없으면 파일명 앞에 `[MRS번호 발급 후 치환]`을 사용한다. 구매 링크가 필요하면 결재 의견글에 기재할 계획을 제시한다. 구매정보 요약용 TXT는 자동 작성·첨부하지 않으며, 사용자가 별도로 요청한 경우에만 작성한다.

## 저장 전/상신 전 점검 및 다음 행동

점검 결과를 `확인됨 / 확인 필요 / 해당 없음`으로 표시한다. 견적·결제방식/VAT·통화·배송비·합계·거래처·품목 분류/코드·자산별 예산·상세 용도·저장위치/납기·필수 첨부를 포함한다.

실제 작업에는 아래 확인 기록을 유지한다. 아직 수행하지 않은 단계는 `미진행`, 실제 값·화면을 대조한 단계만 `확인됨`, 값이 빠지거나 다르면 `누락·불일치`로 적는다. 이 기록은 해당 요청의 작업 상태이며 공유 스킬에 실제 사용자 정보를 저장하지 않는다.

| 단계 | 확인할 결과 | 상태·실제 값 또는 근거 |
|---|---|---|
| 실제 품목 행 입력 | 요청한 N개 품목 중 입력 확정된 n개, 품목코드·수량·단가·행 금액·행 비고·계정범주와 해당 비용센터/예산 | 기본값 변경·빈 행·편집 중 값은 완료 수에 포함하지 않음 |
| 부가정보 입력 확정 | 네 항목의 번호·제목·내용을 입력한 뒤 탭 이동·복귀해 유지 확인 | 기본정보 비고·품목 행 비고와 구분 |
| 입력 확정·저장 직전 | 부가정보 비고 1)~4)의 번호·제목·내용, 품목·합계 | 수행 후 기록 |
| ERP 저장 후 재조회 | 실제 PRQ, 저장된 비고 네 항목과 금액 | 수행 후 기록 |
| 연결된 그룹웨어 본문 | 같은 PRQ·금액, 용도 1)~4) | 수행 후 기록 |
| 상신 직전 첨부 목록 | 준비한 파일명·개수와 목록 일치, 표시되는 크기 확인, 오류 없음 | 수행 후 기록; 목록 정상 등록이면 0%여도 첨부 완료 |
| 상신 직전 설정 | 확인받은 결재선 순서, 수신부서, 공개/메일 실제 선택 상태 | 수행 후 기록 |
| 상신 후 저장된 문서 | 문서번호·식별값, PRQ·비고·결재선·공개 범위, 실제 첨부명·개수·크기 | 수행 후 기록 |
| ERP 상신 결과 | 같은 PRQ의 상신 상태와 연결된 결재문서 식별값 | 수행 후 기록 |

실제 작업 순서: 브라우저 선택(Aside 우선, 사용할 수 없으면 Chrome, 사용자 지정 우선) → 선택한 브라우저 연결·로그인·상신 시 그룹웨어 첨부 권한 점검 → 요청자 소속·직급·사용/납품 위치·관리부서 및 상신 시 결재선 사전 확인 → 기본정보 → 부가정보 비고 네 항목 입력·확정 → 품목 추가 → 품목별 입력/예산 → 비고 재확인·전체 검토 → 최종 저장(PRQ 발급) → 저장된 ERP 비고 재조회 → 구매요청처리(HCT) 조회/결재 → 그룹웨어 용도 네 항목 대조 → 결재선·PI운영파트 수신·그룹웨어 첨부·메일/공개 설정 확인 → 상신 → 저장된 그룹웨어 문서의 첨부 및 ERP 상신 상태 확인. 초안 작성만 요청받았다면 브라우저 준비와 결재선을 요구하지 않는다. ERP 입력·저장만 요청받았다면 그룹웨어 로그인·첨부 권한을 요구하지 않는다.

최종 저장 뒤에는 수정할 수 없다는 점, 종결은 구매팀 접수이며 구매팀 내부 품의 완결 전 발주할 수 없다는 점을 함께 안내한다. 실제 ERP 저장/상신을 하지 않은 경우 그 상태를 명확히 적는다.
