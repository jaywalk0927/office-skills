# 화면별 입력과 복구 방법

2026-10-14까지 실제 사내 ERP·그룹웨어에서 확인한 조작 방법이다. 현재 브라우저 도구가 허용하는 UI API를 사용하며, 아래 선택자·열 이름은 현재 화면에서 확인한 뒤 적용한다. 계정·부서·인명·PRQ·날짜·금액·탭 ID·초안 ID는 실행마다 얻는다. Chrome 전용 연결 복구·팝업 안내는 Chrome을 선택했을 때만 적용한다. Aside에서는 현재 Aside 지침의 지원 방식으로 같은 입력·확인 절차를 수행한다.

## 현재 탭 연결 복구

탭 목록은 정상인데 선택·포커스 단계만 `Emulation.setFocusEmulationEnabled` 등의 시간 초과로 실패하면, 기존 탭 ID·URL을 보존하고 현재 도구가 지원하는 방식으로 **같은 탭을 다시 얻어 상태 읽기를 한 번 시도**한다. DOM 또는 접근성 상태가 읽히면 그 화면에서 계정·메뉴를 확인하고 계속한다. 이 오류만으로 ERP 로그아웃이나 확장 프로그램 재설치가 필요하다고 판단하지 않는다.

상태 읽기까지 실패하면 도구 문서에 있는 동일 탭의 다른 지원 방식이 있는지 확인한다. 새 근거 없이 같은 실패 호출이나 연결 초기화를 반복하지 않는다. 실제 권한 거부·설치 키 인증 오류·사용자 조치 요구가 표시되면 우회하지 않고 해당 조치만 요청한다. 가능한 읽기 경로로도 상태를 확인할 수 없으면 마지막 오류와 필요한 조치를 알리고, 기존 탭과 진행 기록을 유지한다.

## ERP 기본값과 실제 품목 행

- 기본정보를 펼쳐 계정범주·거래처·저장위치·납기를 확인한다. 소모품의 계정범주는 `비용센터`다. `고정자산` 기본값을 그대로 두거나 그 값 때문에 작업을 중단하지 않는다. 품목 추가 후에는 실제 행의 계정범주와 계정상세의 비용센터도 확인한다.
- 기본정보와 부가정보 비고를 확정한 뒤 `추가`한다. 추가하면 상단 기본정보가 잠길 수 있다. 빈 행을 추가한 것은 품목 입력이 아니다. 품목 셀의 검색 UI에서 실제 등록된 E 코드를 조회하고 명칭·규격·단위를 대조한다. 판매 사이트 상품번호를 ERP 품목코드로 쓰지 않는다. 조회하지 않았는데 코드 확인 불가로 보고하지 않는다.
- 기본정보의 `비고`, **부가정보 탭의 `비고`**, 품목 행의 `비고`는 구분한다. 기본정보의 비고에 쓴 값이 품목 추가 후 실제 행으로 전달됐다고 가정하지 않는다. 부가정보에는 용도 네 항목을, 각 품목 행에는 그 품목의 모델·규격·옵션을 넣는다. 여러 품목의 구매 사유를 한 행에 합쳐 넣어 두 품목 입력을 대신하지 않는다.
- 접근성 목록에 표의 셀 값이 없으면 현재 화면의 열 제목과 행을 확인한다. 좌표로 셀을 선택한 뒤 편집 위치를 확인하고 입력한다. Tab 또는 다른 셀로 이동해 확정한 후 행 수·품목·수량·포함단가·금액·행 비고를 다시 읽는다. 상단 기본값만 바뀌었거나 행이 비어 있으면 `일부 입력·미저장`이며, 확인된 요청 내용으로 입력을 계속한다.

## 품목·저장위치 검색이 비어 있을 때

- 소모품인데 제품명·모델 검색이 0건이거나 자산 후보만 나오면, **제품명 → 실제 용도에 맞는 분류명·소모품 → E 코드 후보** 순서로 검색 범위를 넓힌다. ERP의 사무용품·전산용품 같은 분류 품목으로 등록돼 있을 수 있다. 실제 결과의 명칭·규격·단위와 요청 용도를 대조하고, 제품 브랜드·모델·옵션은 행 비고에 적는다. 다른 요청에서 찾은 E 코드를 기본값으로 복사하지 않는다.
- 저장위치의 동 이름 검색이 0건이면 검색어를 줄이거나 지워 등록 목록을 확인한다. 여러 동을 묶은 위치가 있으면 그 명칭이 실제 납품 동을 포함하는지 대조한다. 대응이 명확한 실제 등록값만 사용하고 여러 후보가 남거나 요청 위치가 포함되지 않으면 질문한다.
- 정확한 검색어에서 0건이라는 사실만으로 미등록·확인 불가를 확정하지 않는다. 위 조회 후에도 불명확한 값만 확인 사항으로 남기고, 그 값에 의존하지 않는 입력은 이어간다.

## ERP 품목 단가와 비고

- 카드 구매처럼 VAT 포함으로 설정한 경우, 일반 `단가` 열은 읽기 전용일 수 있다. 가로 스크롤로 **부가세포함단가** 열을 찾아 편집하고 Tab 등으로 확정한다. 수량×포함단가, 행 금액, 전체 합계를 확인한다. 입력이 0으로 남았다고 같은 읽기 전용 셀을 반복 조작하지 않는다.
- 부가정보 비고는 완성한 네 줄을 준비한 뒤 활성 입력란에 실제 키 입력으로 넣고 확정한다. 긴 `pressSequentially` 입력은 도구 제한시간에 맞춰 줄 또는 짧은 구간으로 나눈다. 시간 초과 시 현재 전체 값과 준비 문구를 비교하고, 앞부분이 일치할 때만 커서를 끝으로 옮겨 빠진 뒷부분을 이어 쓴다. 중간 누락·다른 값이 있으면 해당 범위를 먼저 고친다. 처음부터 덧붙여 중복 입력하지 않으며, [필수 비고 확인 단계](chrome-workflow.md#필수-비고-입력과-반영-확인)를 모두 통과해야 한다.
- DOM 읽기 코드에서 얻은 비고 문자열은 도구 밖의 준비 문구와 대조한다. 페이지 안의 평가 코드에서 세션 변수에 접근한다고 가정하지 않는다. 실제 필드 값·그룹웨어 본문을 읽어 비교하며 앱 내부 상태를 직접 바꾸지 않는다.

## 결재 팝업의 제어가 실패할 때

ERP에서 해당 PRQ를 조회·선택하고 `결재`를 한 번 실행해 연결된 초안을 연다. 팝업 조작 실패 후에는 현재 상태를 확인해 클릭이 이미 반영됐는지와 로딩·가림 요소를 구분한다. 같은 조작의 시간 초과를 반복하지 않는다.

1. **현재 팝업에서 입력 방식 전환:** DOM은 읽히는데 locator 입력·클릭만 실패하면, 같은 창의 활성 요소를 도구가 지원하는 접근성 입력·클릭으로 조작하고 결과를 읽는다. 도구 연결을 바꿔야 하면 현재 팝업의 실제 탭 ID/URL로 다시 선택한다. 좌표 입력은 최신 캡처와 편집 위치를 확인한 뒤 사용한다.
2. **일반 탭은 조건부 대안:** Chrome을 선택한 경우, 같은 창의 지원 방식으로도 진행할 수 없고 미저장 편집·첨부가 없다면, 그 창에서 **실제로 관찰한 동일 URL**을 같은 Chrome 프로필의 일반 탭으로 연다. URL의 초안 식별값(`temp_id` 등), 제목의 PRQ, 본문 금액·비고를 대조한 뒤 그 탭 하나에서 편집·상신한다.
3. **일반 탭 열기가 거부되면:** `Tabs can only be moved to and from normal windows` 등이 나오면 창·탭 목록에서 생성 여부를 확인하고, 같은 실패 방식으로 탭 생성을 반복하지 않는다. 기존 팝업에서 아직 시도하지 않은 지원 방식으로 이어가거나 실제 사용자 조치가 필요한 장애를 알린다. 별도 새 결재문서를 만들거나 ERP의 `결재`를 다시 누르지 않는다.

원본에 미저장 편집·첨부가 있으면 먼저 보존·반영 여부를 확인한다. 다른 탭으로 옮겨도 편집이나 파일 대기 목록이 자동으로 전달된다고 가정하지 않는다. 이미 상신된 문서가 있으면 그 저장본을 조회한다.

## 결재자 선택과 순서

1. `결재선` 옆 조직도 아이콘으로 연다. 실제 보이는 조직도 검색 입력란에 이름을 입력하고 검색 결과에 해당 이름·소속·직급이 나타난 뒤 선택한다.
2. 조직도 항목의 체크만으로 결재선에 추가되지 않는다. **선택 목록의 `+`**를 눌러 실제 목록에 들어왔는지 확인한다. 검색 결과가 확인되기 전에 이전 검색의 항목을 누르지 않는다.
3. 새 결재자는 목록 끝, 수신부서 뒤에 추가될 수 있다. 선택 목록에서 추가한 사람을 선택하고 위/아래 이동으로 **기안자 → 확인받은 결재자 순서 → 수신부서**를 맞춘다. 기본 수신부서 `PI운영파트`를 지우지 않는다.
4. 목록과 순서를 확인한 뒤 `저장`한다. 창이 닫힌 뒤 문서의 결재선에도 반영됐는지 한 번 확인한다.

관찰된 DOM에는 활성 창 `.modal.in`, 조직도 검색 `input.nav-search-input`, 추가 `a[data-action="add"]`, 위/아래 이동 `a[data-action="up"]`·`a[data-action="down"]`가 있었다. 여러 숨은 창이 있을 수 있으므로 **현재 보이는 활성 창**으로 범위를 좁힌다. 현재 DOM에 존재하지 않는 선택자를 만들지 않는다.

## 선택자·체크박스 조작 실패

역할 기반 검색이 실패해도 화면에는 대상이 있을 수 있다. 한 번 실패하면 실제 DOM/접근성 상태에서 대상과 가림·로딩 상태를 확인한다. 확인된 CSS 선택자 또는 도구가 지원하는 네이티브 접근성 요소로 전환하고 결과를 읽는다. 좌표가 필요하면 새 화면을 캡처한 뒤 사용한다.

도구 호출의 인자 오류가 나면 현재 도구 문서를 읽고 지원하는 서명으로 고친다. 추측한 키 이름을 바꾸며 반복 호출하지 않는다. 조작 후에는 최신 상태에서 요소를 다시 확인하고, 도구의 오류·성공 반환만으로 ERP 입력의 실패·완료를 단정하지 않는다.

이 화면의 꾸민 체크박스는 `uncheck()`나 텍스트 클릭이 실패했지만 네이티브 접근성 요소 클릭으로 변경된 사례가 있다. `메일보내기`는 아이콘 글리프가 아니라 실제 체크 상태로 확인한다. 공개/비공개도 선택 상태를 읽는다. 상신의견은 실제 편집 iframe 안에 입력·확정한 뒤 내용을 확인한다. 메일·공개 기본값은 현재 사용자 지시로 정한다.

## 상신 후 ERP가 진행 중으로 남을 때

일반 탭에서 저장된 결재문서 번호·PRQ·첨부를 확인했는데 ERP에 `전자결재 진행 중입니다.`가 남아 있다면, 이 요청에서 ERP가 연 **원본 초안 팝업**이 아직 열려 있는지 확인한다. 저장된 결재문서는 유지하고, 같은 초안의 원본 팝업만 닫은 뒤 대기 표시가 사라지면 `조회`한다. 다른 사용자의 창이나 다른 요청의 초안은 닫지 않는다.

ERP에서 같은 PRQ의 `상신` 상태와 저장된 그룹웨어 문서 식별값이 일치해야 확인 완료다. 여전히 불일치하면 저장된 문서를 기준으로 연동 상태를 확인하며 새 PRQ·재상신으로 해결하지 않는다.

## 반복과 대기를 줄이는 방법

- 이미 확인된 값의 입력, Tab 확정, 다음 필드 이동처럼 결정된 동작은 묶고 다음 판단에 필요한 화면을 한 번 읽는다. **검색·선택·팝업 전환은 다음 입력과 분리**한다. Enter 호출이 반환됐어도 이전 결과가 남아 있으면 새 검색 결과의 출현을 확인한다. 선택 후에는 코드·표시명 반영과 팝업 닫힘을 확인하고, 다음 입력란의 포커스를 확인한 뒤 입력한다. Canvas 표에서 스크롤·행 이동으로 위치가 바뀌면 현재 화면을 기준으로 셀을 다시 찾는다. 저장·상신도 실제 결과를 확인한 뒤 이어간다.
- 텍스트 검증은 필요한 필드·목록·본문 영역만 읽는다. 시각적 확인이나 사용자가 볼 증빙이 필요할 때 캡처하고, 같은 사실에 DOM·전체 접근성 트리·스크린샷을 매번 중복 요청하지 않는다. DOM에 셀 텍스트가 노출되지 않는 canvas 표는 화면을 사용한다.
- 고정 시간 대기 대신 검색 결과 출현·로딩 해제·저장된 문서 표시 등 관찰 가능한 조건을 기다린다. 지원되는 짧은 제한시간·중간 반환을 사용하고, 긴 작업 중에는 현재 상태를 알린다. 시간 초과는 성공 여부 미확정으로 기록하고 실제 화면을 확인한다.
- 첨부는 [현재 목록 확인 → 누락 파일만 등록 → 목록 정상 등록 확인](chrome-workflow.md#첨부와-상신-확인) 순서다. **준비한 파일이 목록에 표시되고 오류가 없으면 0%여도 첨부 완료**다. 100% 대기·재업로드·추가 전송·첨부 확인용 상신을 하지 않는다. 파일 전송의 긴 도구 응답과 사이트/권한 오류를 구분하며, 시간 단축을 위해 도구의 승인·보안 절차를 우회하지 않는다.

처리 시간이 길면 느렸던 단계와 관찰한 호출 시간을 기록한다. 스킬 수정만으로 도구·네트워크의 응답 시간을 줄였다고 주장하거나 검증되지 않은 소요 시간을 약속하지 않는다.
