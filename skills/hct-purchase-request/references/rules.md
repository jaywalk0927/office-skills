# 사내 구매요청 작성 규칙

기준 문서: 「260930_구매요청서 작성 방법 안내의 건(ver.1.2)」, 2026-09-30, 총 21쪽. 원본: [source-guide-v1.2.pdf](source-guide-v1.2.pdf). 아래 `p.`는 PDF 쪽수다. 회사 규칙과 스킬이 편의를 위해 제공하는 작성 방법을 구분한다. 더 최신의 회사 안내가 제공되면 차이를 확인해 적용하고 기준 버전을 결과에 표시한다.

## 1. 구매요청 대상과 별도 경로 — p.19

회사의 비용으로 구매하는 품목은 구매 절차를 거친다. 구매팀 품의 없는 건은 비용이 지출되지 않으며, 개인 선지출도 증빙되지 않는다고 안내되어 있다.

| 품목 | 안내문이 정한 경로/예외 |
|---|---|
| 사무용품 | 회사 사무용품 구매 프로세스. 부서 담당자 취합 후 인포메이션 직원 최종 발주. 사무용품 리스트에 없는 품목은 구매요청 가능 |
| 복합기 인쇄용지 | 매월 계약 수량 공급 |
| 복합기 토너 | 최소수량으로 구매요청 가능 |
| 탕비용품 | 부서 담당자 취합 후 인포메이션 직원 최종 발주. 예: 차, 커피, 종이컵, 물티슈 |
| 전산비품 | IT기획파트의 전산 자원 구매요청서 |
| 안전 보호구 | 산업안전보건파트의 안전 보호구 신청서 |
| 교육비 | HR팀 교육품의 후 카드결제 안내 |
| 개인 업무 효율 비품 | 모니터암, 목받이 의자, 버티컬마우스, 손목보호대, 모니터 보안 필름 등. 업무상 필요하면 그룹장 결재 후 구매 가능; 필요성과 해당 승인 확인 |
| 차량 유지관리 비용 | 차량관리 담당부서 법인카드. 예: 세차, 자차수리면책금 |

별도 경로에 해당하는 품목을 일반 MRS로 확정하지 않는다. 예외 여부가 불명확하면 해당 부서/PI팀에 확인할 항목을 제시한다.

## 2. 거래처, 묶음, 결제방식 — p.3, 8, 9, 11, 18

- 일반 거래처 구매는 한 요청서에 한 거래처만 지정한다. 거래처가 여러 곳이면 거래처별 요청서를 작성한다.
- 같은 거래처 구매는 특별한 목적·사유가 없으면 단일 건으로 합친다. 전결규정 회피용으로 나누는 행위는 금지다.
- 세금계산서 발행 후 입금하는 건은 해당 등록 거래처를 지정한다. 등록되지 않은 거래처는 재무팀에 등록 문의 후 진행한다.
- 신용카드 결제는 인터넷 사이트와 현장 카드결제 모두 `기타거래처(I000000030)`를 사용한다. ERP 거래처 검색에서 구분을 `전체`로 해야 조회된다. 검색 결과의 명칭·코드를 대조한다.
- 네이버, 11번가, 오피스디포, Digikey, 컴퓨존 같은 사이트와 이천철물점, 대구이마트 같은 매장을 ERP 거래처로 지정하지 않는다. 이들은 카드 건에서 전부 기타거래처다.
- 기타거래처 카드 구매는 사이트가 달라도 가급적 단일 요청서로 묶는다. 가능한 범위에서 구매 사이트도 통일한다. 동일 제품의 단가 차이가 크지 않으면 네이버/11번가 위주로 한 사이트에 모으는 것이 안내문의 권장사항이다.
- 인터넷 회사 공용계정은 PI팀에 문의한다. 계정이 없는 사이트는 공용계정 생성 요청이 가능하다.

| 결제방식 | 부가세포함여부 | 입력 금액 | ERP 거래처 |
|---|---|---|---|
| 현금결제/세금계산서 | 부가세 별도 | 공급가액 | 해당 등록 거래처 |
| 신용카드 | 부가세 포함 | 배송비를 포함한 최종결제금액 | 기타거래처 |

부가세 설정은 구매팀이 사후 수정할 수 없으며 반려 사유다. 세율을 임의로 정하거나 견적서의 포함/별도 표시를 추측하지 않는다. 현금 건에 VAT 포함 금액만 주어진 경우 공급가액 또는 세율 근거를 확인해 공급가액을 산출한다.

통화는 견적서 그대로 사용한다. 외화를 일부러 원화로 바꿀 필요가 없다. 서로 다른 통화나 결제방식은 기본정보가 충돌하므로 묶음 가능 여부를 확인한다. 이 확인은 입력 구조상 필요한 판단이며 안내문에 별도의 혼합 기준은 없다.

## 3. 품목 분류와 코드 — p.8–11

| 구분 | 판단 기준 | 계정범주 | 품목코드 |
|---|---|---|---|
| 고정자산 | 개당 단가 100만원 이상이며, 1년 이상 관리·수리하여 사용 가능 | 고정자산 | ERP의 해당 고정자산 품목 |
| 상품 | 판매 목적으로 구매하는 품목 | 기본계정 | ERP의 해당 상품 품목 |
| 소모품 | 그 밖의 품목 | 비용센터 | 소모품 E 코드 |

- 연간 라이선스, 폭파시험용 지그 등은 소모품으로 처리한다. 가격만으로 자산으로 분류하지 않는다.
- 일반 소모품에는 반드시 소모품 E 코드를 사용한다. 예시 화면의 `E99999999`는 예시이며 모든 소모품의 공통코드라는 규칙은 없다.
- 자산/소모품, 품목 구분 및 예산계정이 모호하면 저장 전에 PI팀에 문의한다.
- 외화 품목의 100만원 기준 충족 여부가 불명확하면 분류 확인용 환산근거를 따로 확인한다. ERP 요청 통화는 견적 통화를 유지한다.

## 4. 고정자산 투자예산 — p.9–10

고정자산은 **각 품목을 선택하여** 계정상세에서 예산단위와 예산계정을 지정한다.

- 예산단위: 안내문 기준 `투자예산(2026)`, 코드 `9992026`. `투자예산` 검색 결과의 동일한 코드 항목은 어느 것을 선택해도 된다고 명시되어 있다.
- 예산계정: 구매요청 센터의 실제 투자예산 항목을 선택한다. 예시 화면의 `통신1센터-01`과 같은 항목을 다른 사용자에게 그대로 적용하지 않는다.
- 소모품에 투자예산을 지정하거나 잘못된 예산계정을 선택하면 발주입력 단계에서 구매팀이 수정할 수 없다. 전자결재 반려 후 요청서 재작성이 필요하다.
- 소모품은 이 안내문의 투자예산 입력 대상이 아니다. 소모품의 별도 비용 예산계정은 안내문이 필수 입력으로 정하지 않았다. 추가 예산 필드는 실제 ERP에서 필수로 확인되거나 사용자가 별도 회사 규정을 제공한 경우에만 확인한다.
- `2026`과 `9992026`은 **2026년 안내문의 값**이다. 다른 연도 요청은 해당 연도의 ERP 값이나 최신 회사 안내를 확인하고, 연도만 바꾼 코드를 만들어 쓰지 않는다.

## 5. 용도, 옵션과 비용 — p.7, 9, 11, 18

부가정보 탭의 비고는 전자결재의 용도에 들어간다. 실질적인 품의 내용이며, 상세 내용이 없으면 보완요청 또는 반려된다. 다음 네 항목의 **번호·제목·내용을 모두 필수로 작성**한다. 품목 행 비고와 별개의 입력란이다.

```text
1) 구매목적: 구매가 필요한 업무와 사유
2) 사용장소: 실제 사용 장소
3) 관리부서: 실제 관리 팀/파트
4) 상세내용: 모델/규격, 수량 근거, 대체/증설 등 확인된 상세 사유
```

스킬의 실행 확인 방법: 빈 항목이나 미확정 값이 있으면 실제 저장·상신을 진행하지 않는다. 저장 직전 입력 확정값, 저장 후 재조회한 ERP 비고, 상신 전 그룹웨어 본문의 용도에서 네 항목을 각각 대조한다. 세부 절차는 [필수 비고 입력과 반영 확인](chrome-workflow.md#필수-비고-입력과-반영-확인)을 따른다.

실제 납품받는 동은 기본정보와 품목별 `저장위치`에 입력한다. 사용장소와 납품 위치가 다르면 각각 기록한다. 품목 행 `비고`에는 모델·규격·상세 옵션을 반드시 적는다. 일반 사유만으로 품목을 식별할 수 있다고 간주하지 않는다.

- 배송비는 별도 품목으로 만들지 않고 제품금액에 포함한다.
- 견적의 운임·인건비·기타 잡비용도 가급적 제품금액에 포함한다.
- 카드 건은 배송비 포함 최종결제금액을 입력한다.
- 구매링크는 ERP 비고의 글자수 제한을 고려해 필요한 경우 의견글 또는 TXT 첨부파일로 제공한다. 정확한 글자수 상한은 안내문에 없다.

안내문의 TXT는 구매 링크 제공 방법의 선택지이며 필수 첨부가 아니다. 스킬은 구매정보 요약용 TXT를 자동 작성·첨부하지 않고 필요한 링크를 의견글에 기재한다. TXT 작성은 사용자가 별도로 요청한 경우에만 한다. 분류별 필수 증빙은 그대로 확인한다.

스킬 작성 방법: 배송비 등이 여러 품목에 공통으로 붙으면 배분근거와 품목별 반영 금액을 명시하고 합계를 맞춘다. 한 종류/동일 단가의 여러 개는 총 배송비를 수량으로 나눈 단가를 제안할 수 있다. 여러 품목의 배분 방식이나 원단위 반올림이 불명확하면 배분안을 확인하고 확정한다. 안내문이 특정 배분 공식을 지정한 것은 아니다. 할인과 부대비용을 중복 가산하지 않는다.

## 6. ERP 기본 설정과 입력 순서 — p.4–9

### 최초 한 번의 컬럼 설정

경로: `구매관리 > 구매발주관리 > 구매요청관리 > 구매요청입력`.

VAT 포함 컬럼을 보이게 하려면 부가세포함여부를 `포함`으로 설정한 뒤 가운데 회색 화살표 `EDIT`를 누른다. 다음 순서로 컬럼을 정렬하고 출력여부를 전부 YES로 설정한 후 컬럼 설정을 저장한다. 고정여부는 자유다.

```text
계정범주 / 품목 / 품목명 / 규격 / 요청수량 / 요청단가 /
부가세포함단가 / 요청금액 / 부가세포함금액 / 비고 /
거래처 / 저장위치 / 납기예정일
```

이는 **화면 설정을 위한 VAT 포함 전환**이다. 실제 작성 시 부가세포함여부는 결제방식에 맞게 다시 설정한다.

### 요청서 입력

1. 기본정보 입력. 숨겨진 항목은 우측 접기/펼치기 버튼으로 펼친다.
   - 공장/요청자/요청일: 실제 사용자 정보. 안내 화면의 `공장명`은 예시 표시값이므로 이번 요청의 실제 공장 선택값과 대조한다.
   - 구매그룹: 실제 구매요청부서의 팀/파트.
   - 구매조직: `Default 구매조직`.
   - 요청유형: `구매요청`.
   - 부가세포함여부: 실제 결제방식에 따른 포함/별도.
   - 통화: 견적 통화.
   - 계정범주, 거래처, 저장위치, 납기: 실제 요청 내용.
2. 부가정보 탭 비고에 네 항목의 상세 용도 작성.
3. 기본정보·부가정보 입력을 완료한 후 `추가`로 품목 생성. 추가하면 위 기본정보 컬럼이 잠긴다. 품목 삭제 시 수정 가능하다고 명시되어 있다. PRQ 발급 후 수정 가능하다는 의미는 아니다.
4. 품목별 분류/계정범주, 실제 품목코드, 수량·단가, 상세 옵션, 거래처·저장위치·납기 확인.
5. 자산 품목마다 예산단위·예산계정 지정.
6. 저장 전 전체 검토 후 최종 저장. MRS 번호가 `PRQ…`로 채번된다.

사용자 입력을 단순히 화면 예시 값으로 채우지 않는다. 구매유형·라인유형·계정배분유형·세무구분 등 본문에서 고정값으로 지시하지 않은 필드는 실제 ERP/사내 기준을 따른다.

## 7. 전자결재, 결재선과 첨부 — p.12–16

경로: `구매관리 > 구매관리(HCT) > 구매요청처리(HCT)`.

1. 이번 요청서에서 확인된 실제 공장 선택값, 구매요청일 범위, 필요시 요청번호로 조회한다. 안내 화면의 공장 예시를 현재 값으로 복사하지 않는다.
2. 상신할 요청번호를 선택하고 우측 상단 `결재`를 누른다.
3. 결재선은 실제 전결규정에 따른다. 구매요청서는 최대 그룹장까지 진행한다.
4. 수신부서는 `PI운영파트`로 고정한다. 참조/열람 기본값은 유지한다. 안내문 예시 인명은 고정 결재자 명단이 아니다.
5. 생성된 구매요청 본문에 미작성·오기입이 없는지 재검토한다.
6. 그룹웨어 결재창에서 필요한 자료를 첨부하고 상신한다.

스킬 실행 방법: 파일은 그룹웨어에만 등록하며 ERP에는 첨부하지 않는다. 실제 첨부 여부는 그룹웨어 결재문서에서 확인하고, ERP에서는 요청서의 상신 상태와 연결된 결재문서 식별값을 확인한다.

구매요청처리 화면의 `요청취소`, `요청확정`, `확정취소`, `요청마감`, `마감취소` 등은 구매팀 관리 기능으로 조작 금지다.

### 분류별 필수 첨부

| 분류 | 필수 자료 | 조건부 자료/예외 |
|---|---|---|
| 고정자산 | 견적서, 용도설명서, 장비 카탈로그, 해당 투자자료 | 1억원 이상: 투자타당성보고서 및 투자검토의견서. 5억원 이상: 투자심의의결서 추가. 투자검토/심의 관련 문서는 재무팀(안내문 담당: 박현범 ES)을 통해 진행 |
| 상품 | 공급자 견적서, 사내 발행 견적서, 고객사 발주서 | 일반 견적서 하나로 대체하지 않음 |
| 소모품 | 견적서 | 기타거래처 인터넷 구매는 장바구니 또는 제품 상세페이지 스크린샷으로 대체 가능. 제품명·옵션·수량 등 구매에 필요한 모든 정보가 보여야 함 |

투자 금액의 VAT 포함/별도 기준이나 외화 환산 기준은 안내문에 따로 명시되어 있지 않다. 임계금액 해당 여부가 불명확하면 재무팀 확인 항목으로 남긴다. 상품·고정자산에는 소모품 스크린샷 대체 예외를 일반화하지 않는다. 첨부 상태는 실제 파일을 읽거나 열어 확인한 것과 사용자가 있다고 말한 것을 구분한다.

### 파일명

```text
MRS번호_자료종류_요청품목(거래처명).확장자
```

원문 예시: `PRQ20260800001_견적서_MT8000A 중고(롯데렌탈)`.

MRS 번호는 저장으로 발급받은 **실제 PRQ**다. 아직 발급 전이면 `[MRS번호 발급 후 치환]`으로 파일명 계획만 만든다. 자료종류·요청품목·실제 견적 거래처명을 쓰고 원래 확장자를 보존한다. 카드 건에서는 ERP 거래처가 기타거래처여도 원본 증빙의 실제 사이트/판매처를 파일명에 식별 가능하게 남긴다. 후자의 표기는 스킬의 정리 권장사항이며 별도의 회사 고정값은 아니다.

## 8. 수정 제한과 상태 — p.3, 15

최종 저장/PRQ 채번 이후 요청 내용은 수정할 수 없다.

| 현재 단계 | 원문이 정한 정정 절차 |
|---|---|
| 전자결재 작성 전 | 기존 요청 데이터(PRQ)는 그대로 두고 새 요청서 작성 |
| 전자결재 작성 후 완결 전 | 회수 후 새 구매요청서 작성 |
| 전자결재 완결 이후 | 구매팀에 즉시 연락. 재상신 또는 전자결재 의견글 기재 후 구매팀 사후 처리 등 안내에 따라 조치 |

기존 요청서 변경 기능이나 회수 후 기존 PRQ 편집을 제안하지 않는다. 새 요청서가 기존 건을 대체함을 실제 번호와 사유로 식별하고, 구매팀 관리 취소 버튼을 임의로 조작하지 않는다.

| 결재상태 | 의미 |
|---|---|
| 저장 | 전자결재 상신 전 저장 상태 |
| 상신 | 구매요청 전자결재 진행 중 |
| 종결 | 구매요청 전자결재 완결, 구매팀 접수 |
| 취소 | 반려된 요청도 취소 상태로 조회됨 |

종결 이후 구매팀이 별도 `구매 품의`를 진행한다. 구매요청서 접수가 바로 발주로 이어지지 않는다.

## 9. 발주, 카드와 문의 — p.17–18, 20

- 구매팀 품의 완결 전 선발주 금지. 예외가 필요하면 PI팀 사전 협조가 필수다.
- PI팀을 통하지 않은 발주는 그룹장 결재 사유서 제출 및 경고 대상으로 안내되어 있다.
- 원칙은 요청서 작성 후 구매팀이 결제하는 것이다. 긴급 현장 카드결제는 구매팀 구매카드 불출을 문의한다.
- 팀내 불출 법인카드 사용은 금지다. 이미 사용한 경우 취소 후 구매카드 재결제가 필요하다고 안내되어 있다.
- 긴급 예외로 PI팀 협의 후 구매카드를 사용하는 경우 당일 즉시 반납하고 구매요청서를 사후 작성한다.
- 구매 업무 문의는 경영기획실 PI팀(PI운영파트). 거래처 등록과 투자검토/심의 의견서는 재무팀. 실제 문의 전송은 사용자의 명시 요청이 있을 때만 한다.
