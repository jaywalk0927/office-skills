# 브라우저 작업과 사전 점검

실제 ERP 입력·저장·전자결재 상신을 요청받았을 때 적용한다. 초안 작성만 요청받으면 이 준비는 필요 없다. 회사 구매 규칙은 [rules.md](rules.md)를 따른다. 아래는 2026-10-14까지 확인한 브라우저 작업 방법이며, 화면이 바뀌면 현재 UI를 다시 확인한다. ERP 품목 입력 또는 그룹웨어 조작을 시작할 때 [화면별 입력과 복구 방법](chrome-ui-notes.md)의 해당 부분을 읽는다.

## 진행 상태와 확인 기록

현재 요청에서 확정된 입력값·승인 범위, 선택한 브라우저·프로필과 작업 탭, 준비한 비고 원문, 첨부 파일명·크기, 실제 PRQ, 연결된 결재 초안 URL, 상신 후 문서번호·식별값을 실행 상태로 유지한다. 대화가 길어지거나 도구 호출이 중단돼도 이 기록과 현재 화면으로 이어간다. 이 값들은 해당 실행의 대화·작업 기록에만 두고 스킬·공유 ZIP에는 넣지 않는다.

필수 확인 결과는 `미진행 / 확인됨 / 누락·불일치`로 기록한다. `확인됨`에는 실제로 읽은 값이나 화면 근거가 있어야 한다. [결과 양식](../assets/output-template.md#저장-전상신-전-점검-및-다음-행동)의 단계별 표를 사용한다. 같은 단계·같은 입력값에서 확인된 항목은 재조회하지 않는다. 저장·상신·편집·재접속으로 상태가 바뀌면 해당 단계의 검증을 수행한다. 특히 저장 전 화면과 저장 후 ERP, 상신 전 목록과 저장된 결재문서는 서로 다른 확인 단계다.

품목별로 `미조회 / 조회했으나 미확정 / 입력 중 / 입력 확정·확인됨`을 구분한다. 입력 확정에는 실제 품목코드·식별 정보, 수량·단가·행 금액, 계정범주와 해당 비용센터/예산, 행 비고가 필요하다. 기본정보의 기본값이나 편집 중 셀의 텍스트를 실제 품목 행으로 계산하지 않는다. 입력 후 Tab 또는 다른 셀로 이동해 값을 확정하고 현재 행을 다시 읽는다. 행이 사라지거나 값이 비면 해당 항목을 미입력으로 되돌려 보완한다.

## 시작 전 확인

실제 브라우저 작업이 필요할 때만 Aside의 설치·도구 존재를 확인한다. 사용자가 브라우저나 특정 탭을 명시하면 그 선택을 우선하며, 읽어 달라고 지정한 사이드패널 탭도 사용할 수 있다.

별도 지정이 없고 Aside 도구나 CLI가 있으면 현재 Aside 지침(`aside-browser` 스킬, CLI 사용 시 `aside guide`)을 먼저 읽고 연결·탭 상태를 확인한다. 사용 가능하면 Aside를 사용한다. 미설치·비실행·연결 불가 등으로 Aside를 사용할 수 없으면 설치를 요구하지 않고 Chrome으로 진행한다. 선택한 브라우저의 기존 ERP 업무 탭을 우선 재사용하며, 없으면 그 브라우저에 [사내 ERP](https://erp.hcterp.com/) 새 업무 탭을 연다. Chrome을 선택한 경우에도 기존 Chrome 업무 탭을 먼저 찾는다. 브라우저·프로필·탭 ID는 실행 때 확인한다.

도구 권한 거부는 Chrome 등 다른 브라우저로 전환해 우회하지 않고 도구의 승인·보안 요구를 따른다. 브라우저 전환 전 미저장 입력·첨부와 기존 PRQ·결재문서의 접수 여부를 확인한다. 상태가 불명확하면 보존·조회부터 하고, 전환을 이유로 요청서·결재문서를 다시 생성하지 않는다. 브라우저 선택은 저장·상신 등 업무 권한을 추가하지 않는다.

| 조건 | 확인 방법과 미충족 시 처리 |
|---|---|
| 브라우저 제어 연결 | 선택한 브라우저의 실제 탭 상태를 읽을 수 있는지 확인한다. Chrome을 선택했고 탭 목록은 보이지만 선택·포커스가 시간 초과되면 [현재 탭 연결 복구](chrome-ui-notes.md#현재-탭-연결-복구)를 적용한다. 도구의 연결·설치 키 인증 오류는 ERP 로그인 실패의 증거가 아니다. 사용자 조치가 필요한 경우 연결·확장 조치만 요청한다. 인증 키 초기화·재설치를 임의로 시도하지 않는다. 브라우저 전환은 위 선택 규칙과 상태 확인 절차를 따른다. |
| ERP 로그인·메뉴 접근 | 현재 로그인 계정과 요청에 필요한 메뉴가 보이면 확인 완료다. 로그인 화면·세션 만료·인증 실패가 보이면 사용자에게 직접 로그인해 달라고 즉시 요청한다. 비밀번호·OTP를 채팅으로 받지 않는다. 로그인 계정·요청자가 다르면 임의로 동일인으로 처리하지 않는다. 로그인은 됐지만 메뉴가 없으면 메뉴 접근 문제로 따로 알린다. |
| 전자결재 접근 | 그룹웨어 결재 작업이 포함됐으면 선택한 브라우저의 같은 프로필에서 사내 그룹웨어 로그인과 접근을 확인한다. 실제 PRQ와의 결재 연결은 해당 요청서를 조회한 뒤 확인한다. 접근 확인을 위해 새 요청서를 저장하거나 결재문서를 만들지 않는다. |
| 사이트 제어 권한 | 브라우저 도구가 ERP 또는 연결된 그룹웨어에 대한 권한을 요구하면 해당 사이트에 필요한 권한만 안내한다. |
| 그룹웨어 로컬 파일 첨부 권한 | 그룹웨어에 로컬 파일을 등록하는 작업이 포함된 경우에만 확인한다. 도구가 권한 상태를 제공하면 확인하고, 상태를 알 수 없으며 이번 세션의 설정 완료 답변도 없으면 사용자에게 묻는다. ERP 입력·저장만 요청받으면 해당 없음이다. 로그인 성공만으로 파일 첨부 권한이 있다고 판단하지 않는다. |
| 첨부파일 준비 | 그룹웨어에 등록할 파일의 존재·내용·확장자·크기를 확인한다. PRQ 발급 전에는 파일명 계획을 만들고 발급 후 실제 번호를 반영한다. 다른 사람 PC의 경로를 복사하지 않는다. |

Chrome을 선택한 경우에만, 로컬 파일 첨부 권한이 없거나 확인되지 않으면 다음과 같이 안내한다. **Chrome → 확장 프로그램 관리 → 브라우저 제어용 확장 프로그램의 세부정보 → ‘파일 URL에 대한 액세스 허용’**을 사용자가 직접 확인·설정하도록 한다. 이 설정이 확장 프로그램의 로컬 파일 접근을 허용한다는 점을 짧게 설명한다. 브라우저 도구로 보안 설정 페이지를 우회해 조작하지 않는다. 설정 변경 후 연결·프로필·탭 목록을 새로 확인한다. 기존 탭이 남아 있으면 재사용하며, 도구가 요구하면 Chrome 작업 연결을 다시 시작한다. 근거: [공식 Chrome 확장 안내의 파일 업로드](https://learn.chatgpt.com/docs/chrome-extension#upload-files). Aside의 첨부는 현재 Aside 지침과 권한 절차를 따른다.

확인 결과는 예를 들어 `선택한 브라우저 연결·ERP 로그인 확인됨 / 첨부 권한은 사용자 확인됨 / 그룹웨어 로그인 확인 필요`처럼 짧게 알린다. 미확인 조건에 의존하는 실제 작업은 기다리고, 자료 정리는 이어갈 수 있다. 이미 확인된 설정·로그인·사용자 답변은 반복해서 묻지 않는다.

로그인이 필요할 때는 다음처럼 대상과 재개 조건을 구체적으로 안내한다: `현재 작업 중인 브라우저의 사내 ERP에서 로그인이 필요합니다. 열어 둔 ERP 탭에서 직접 로그인한 뒤 “로그인 완료”라고 알려주세요. 확인 후 작성하던 요청서에서 이어가겠습니다.` 탭을 유지하고 사용자 조치를 기다린다. 완료 답변 뒤 그 탭의 계정·메뉴를 읽어 실제 로그인을 확인하며, 여전히 로그인 화면이면 그 사실과 필요한 조치만 알린다. 기다리는 동안 다른 사이트의 로그인·메일 작성·수신자 검색으로 작업을 바꾸지 않는다. 사용자가 다른 작업을 하지 말라고 했으면 자료 정리도 진행하지 않는다.

## 입력·결재 연결

1. 요청자·소속, 사용/납품 위치·관리부서와 구매정보를 기존 답변에서 재사용한다. 상신 요청이면 결재정보도 준비하되, 빠진 정보가 영향을 주는 단계만 보류한다. 회사 규칙에 따라 기본정보와 부가정보 비고 네 항목을 작성·확정한 뒤 실제 품목 행을 추가한다. 확정된 소모품은 `비용센터`로 선택하고 품목 검색에서 E 코드를 조회한다. 각 행의 품목·수량·단가·행 비고를 입력·확정하고 계정상세의 비용센터를 확인한다. VAT 포함 건은 **부가세포함단가** 열을 사용한다. 한 품목이 미확정이어도 독립된 확정 입력은 마치며, 자동 날짜·구매그룹은 실제 요청과 대조한다. 기본값·빈 행만 남겨 두고 입력 완료로 보고하지 않는다.
2. 아래 필수 비고 확인을 마친 뒤 최종 저장하고 실제 PRQ를 기록한다. 저장된 ERP를 재조회해 비고의 네 항목과 내용을 확인한다. 저장된 요청서의 결재는 `구매요청처리(HCT)`에서 **그 PRQ를 조회·선택 → 결재**로 연다. 연결되지 않은 별도 결재문서를 수동 생성하지 않는다.
3. 새 결재창이 열리면 선택한 브라우저의 새 탭·창 목록에서 실제 연결된 문서를 찾고 URL과 PRQ를 기록한다. 연결이 지연되면 기존 PRQ와 열린 창부터 확인한다. 팝업의 입력·클릭·캡처가 실패하면 [현재 팝업부터 복구하는 순서](chrome-ui-notes.md#결재-팝업의-제어가-실패할-때)를 적용한다. 중복 저장·결재창 생성을 반복하지 않는다.
4. 입력 전에 받은 결재 순서와 이름·직급·직책을 실제 조직 검색 결과의 소속·인명과 대조한다. 동명이인이나 부서 차이가 불명확하면 묻는다. 요청자의 직급만으로 결재자를 추정하거나 이전 사용자의 결재선을 복사하지 않는다. **‘결재선’ 옆 조직도 아이콘**으로 추가한다. 참조·열람권자의 아이콘과 혼동하지 않는다. 수신부서 `PI운영파트`와 참조·열람 기본값은 회사 규칙대로 유지한다.
5. 메일 알림과 공개/비공개는 사용자 지시를 적용한다. 지시가 없으면 상신 전에 선호를 묻는다. 한 사용자의 선택을 다른 요청의 고정값으로 만들지 않는다. 이미 상신을 요청·승인받았다면 같은 실행 허락을 다시 묻지 않는다.

## 필수 비고 입력과 반영 확인

회사 안내문의 필수 비고는 **부가정보 탭의 비고**다. 기본정보의 기본 비고나 품목 행 비고와 혼동하지 않는다. [회사 양식](rules.md#5-용도-옵션과-비용--p7-9-11-18)의 `1) 구매목적 / 2) 사용장소 / 3) 관리부서 / 4) 상세내용`을 각각 별도 줄로, 번호·제목·확인된 실제 내용까지 모두 입력한다. 제목만 있거나 `[확인 필요]`가 남은 값은 실제 저장에 사용할 수 없다.

1. **품목 추가 전:** 기본정보를 채운 뒤 부가정보 비고에 완성한 네 항목을 입력한다. 현재 보이는 활성 입력란인지 확인한다. `fill` 호출 성공이나 입력 직후 화면 표시만으로 반영됐다고 판단하지 않는다. 도구가 지원하는 정상 입력 방식으로 입력하고 Tab 등 화면의 입력 확정 동작을 수행한다. 다른 탭으로 이동했다가 부가정보로 돌아와 값을 다시 읽는다.
2. **최종 저장 직전:** 품목과 금액 입력을 마친 뒤 부가정보 탭을 다시 열어 네 항목의 번호·제목·내용을 준비한 문구와 대조한다. 품목 행 비고의 모델·규격·옵션도 별도로 확인한다. 누락됐으면 이미 받은 답변으로 보완하고 입력 확정·재확인을 다시 수행한다. 확인 전에는 저장 버튼을 누르지 않는다.
3. **저장 직후:** 발급된 실제 PRQ를 기록하고, 해당 PRQ를 ERP에서 재조회해 부가정보 비고를 읽는다. 저장 전 화면에 남아 있던 값은 저장 결과의 증거로 사용하지 않는다. 네 항목이 누락됐으면 결재 연결·상신을 중단하고 회사의 저장 후 정정 절차를 적용한다.
4. **상신 직전:** 연결된 그룹웨어 본문의 `용도 (상세히 기재)`에 같은 네 항목과 내용이 모두 있는지 확인한다. 본문이 iframe이면 실제 문서 영역에서 확인한다. 입력창·첨부·의견글에만 있는 내용은 본문 반영으로 인정하지 않는다. ERP 비고가 정상인데 용도에서만 누락되면 연결·전달 문제부터 확인한다. 해당 건을 상신하거나 새 PRQ 발급을 반복하지 않는다.

확인 근거는 해당 단계의 실제 화면이나 읽은 필드 값으로 남긴다. 비고 누락 건은 기존 PRQ와 미상신 상태를 구분해 기록하고, 사용자에게 이미 받은 개인정보를 다시 묻지 않는다. 정정본에서도 저장 후 누락되면 추가 발급을 멈추고 입력 반영 문제를 해결한다.

이 화면에서는 입력값이 보였지만 저장 뒤 사라진 사례가 있었다. 기본정보를 확정한 뒤 도구가 지원하는 실제 키 입력(`pressSequentially` 등)으로 비고를 넣고 Tab으로 확정했을 때 저장·재조회와 그룹웨어 전달까지 유지되는 것을 확인했다. 이 입력 방식을 우선 사용하되, 원인을 특정 입력 함수의 문제로 단정하지 않는다. 긴 문구는 호출 시간 제한 안에서 나눠 입력하고, 중단되면 현재 필드에서 입력된 범위를 읽은 뒤 빠진 부분만 이어 쓴다.

## 장바구니 증빙 준비

회사 규칙에서 스크린샷 대체를 허용하는 인터넷 소모품 구매는 **장바구니 담기 → 요청 품목·수량·금액 대조 → 장바구니 캡처**를 우선한다. ERP 최종 저장 전에 준비해 확인된 장바구니 금액과 ERP 입력값을 대조한다. 한 품목도 가능하면 이 방법을 쓰고, 같은 판매처의 여러 품목은 한 장바구니에 모아 첨부 수를 줄인다. 판매처가 다르면 사이트별로 준비한다. 상품·고정자산의 필수 견적서 등은 장바구니 캡처로 대체하지 않는다.

1. 현재 장바구니를 먼저 확인하고 요청 품목의 확정된 모델·옵션·수량을 맞춘다. 담기 후 안내 알림이 나타나면 내용을 확인해 처리하고 **실제 장바구니의 품목 행**을 읽는다. 상단 배지의 숫자가 그대로라는 이유만으로 실패·로그인 필요를 판단하거나 다시 담지 않는다. 이미 담긴 동일 품목을 중복 추가하지 않는다. 요청과 무관한 기존 품목은 임의로 삭제하지 않으며, 선택 기능이 있으면 이번 요청 품목만 선택해 합계를 확인한다. 기존 품목과 이번 요청의 구분이 불명확하면 사용자에게 확인한다.
2. 판매처, 각 제품명·모델/옵션·포장단위·수량·가격, 상품 합계와 표시된 배송비·할인·최종금액을 대조한다. 기존 확인값과 차이가 있으면 원인을 확인하고 필요한 값만 사용자에게 묻는다. 장바구니에 표시되지 않는 배송비·VAT 등은 확인된 자료나 사용자 답변으로 보완하며 추정하지 않는다.
3. 요청 품목 전체와 합계가 읽히는 **장바구니 스크린샷 한 장**을 우선 준비한다. 길면 도구가 지원하는 전체 페이지 캡처를 사용한다. 한 장에서 글자가 읽히지 않거나 필수 정보가 빠지면 필요한 부분만 나눠 캡처하고, 장바구니에 없는 규격·옵션만 상품 상세페이지로 보완한다. 같은 정보를 품목마다 중복 캡처하지 않는다. 파일명은 `실제PRQ_장바구니_요청품목또는품목N종(실제판매처).원래확장자`로 정리하며, PRQ 발급 전에는 기존 파일명 계획 규칙을 따른다.
4. 로그인·사이트 기능·품절 등으로 장바구니 준비가 불가능하면 사유를 짧게 알리고 회사 규칙이 허용하는 상품 상세페이지 캡처로 준비한다. 초안만 요청받았으면 받은 장바구니 자료를 활용하며 사이트 조작을 추가로 요구하지 않는다. 장바구니 담기는 증빙 준비이며, 주문·카드 결제는 사용자가 요청한 별도 범위를 따른다.

## 첨부와 상신 확인

회사 규칙의 분류별 필수 증빙을 준비한다. 구매정보를 다시 적는 TXT는 자동으로 작성·첨부하지 않는다. 필요한 구매 링크는 결재 의견글에 남기고, TXT 작성은 사용자가 별도로 요청한 경우에만 한다.

파일은 **그룹웨어 결재창에서만 등록**한다. ERP의 파일 첨부 기능은 사용하지 않으며, ERP에서 파일이 자동 전달될 것을 전제로 진행하지 않는다. 그룹웨어의 실제 첨부 목록을 읽고, 필요한 파일이 없으면 **‘파일추가’**를 눌러 도구가 지원하는 파일 선택 방식으로 준비된 로컬 파일을 등록한다. 이미 등록된 파일은 중복 추가하지 않는다. 파일명·크기·개수를 대조하고, 화면이나 연결 상태가 바뀐 뒤에는 목록을 다시 읽는다.

파일 선택창 이벤트를 사용하는 도구는 이벤트 대기를 시작한 뒤 `파일추가`를 누르고 실제 절대 경로를 전달한다. 등록 호출이 지연되거나 시간 초과돼도 실패로 단정하지 말고 현재 첨부 목록부터 확인한다. 같은 파일을 다시 등록하기 전에 이전 호출의 완료 여부와 목록을 대조한다. 권한 오류와 느린 응답은 구분하고, 실행 차단은 우회하지 않는다.

| 화면 상태 | 다음 행동 |
|---|---|
| 파일이 목록에 없음 | 파일추가로 등록하고 목록을 다시 확인한다. 등록하지 않은 파일을 첨부 완료로 보고하지 않는다. |
| 목록에 파일이 있고 전송률 0%, 오류 없음 | 상신 전 대기 상태일 수 있다. 별도 전송 버튼이 있으면 사용한다. 이번에 확인한 사내 화면은 결재상신 후 최종 확인에서 전송됐다. 별도 버튼이 없고 상신 권한이 확보됐으면 정상 상신 절차를 진행하고 저장된 문서에서 확인한다. 100% 표시를 무한 대기하거나 같은 파일을 중복 등록하지 않는다. |
| 업로드 오류·필수 첨부 누락 또는 도구의 실행 차단 | 오류를 해결한 뒤 진행한다. 실행이 차단되면 우회하지 않고 차단 사유를 설명하며 필요한 사용자 조치를 요청한다. |
| 상신 결과 불명확 | 기존 결재문서와 ERP 상태를 조회한다. 같은 PRQ를 다시 상신하기 전에 중복 여부부터 확인한다. |

상신 후에는 저장된 그룹웨어 결재문서를 열어 **문서번호, 연결된 PRQ, 결재선, 공개 범위, 실제 첨부파일명·개수·크기**를 대조한다. ERP에서는 같은 PRQ의 `상신` 상태와 연결된 결재문서 식별값을 확인하며, ERP 첨부 건수는 검증·완료 기준으로 사용하지 않는다. 목록의 0% 표시는 업로드 완료 근거가 아니며, 그룹웨어 문서의 첨부 목록·열람 또는 다운로드 링크 등 확인 가능한 근거로 결과를 판단한다. 확인되지 않은 항목은 그대로 보고한다.

일반 탭에서 같은 결재문서의 상신을 마쳤는데 ERP가 `전자결재 진행 중입니다.`에 머물면, [원본 팝업 종료 후 ERP 조회](chrome-ui-notes.md#상신-후-erp가-진행-중으로-남을-때)를 적용한다. 대기 표시를 새 상신이 필요한 근거로 해석하지 않는다.

첨부가 빠져 있으면 문서를 다시 조회해 누락인지 확인한다. 누락이 확인되면 `상신됨·첨부 보완 필요`로 알리고, 현재 문서에서 허용되는 첨부 보완 방법을 확인해 요청 범위 내에서 처리한다. 회수·새 요청서 작성 등이 필요하면 회사의 정정 절차와 사용자 승인 범위를 확인한다. 전체 작업을 완료했다고 보고하거나 같은 PRQ를 곧바로 재상신하지 않는다.

완료 보고에는 PRQ·결재문서번호/링크·현재 결재 상태·첨부 확인 결과를 짧게 적는다. `상신`과 최종 결재 완료, 구매팀 접수·발주는 구분한다.
