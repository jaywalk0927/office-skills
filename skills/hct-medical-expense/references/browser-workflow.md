# 그룹웨어 작업 절차

## 브라우저 선택과 접속

1. 실제 브라우저 작업이 필요하면 **Aside 설치·도구 제공 여부와 연결 상태**부터 확인한다. 사용 가능한 Aside가 있으면 해당 환경의 Aside 지침(설치된 `aside-browser` 스킬 또는 `aside guide`)을 읽고 Aside에서 진행한다. **미설치·비실행·연결 불가면 Chrome**의 기존 사내 그룹웨어 탭을 재사용하고, 없으면 Chrome에 [사내 그룹웨어](https://gw.hct.co.kr)를 연다. 이 선택 때문에 Aside 설치나 실행을 사용자에게 요구하지 않는다.
2. 사용자가 특정 브라우저·탭을 명시한 경우 그 선택을 우선한다. 예를 들어 읽으라고 지정한 사이드 탭은 그 탭에서 읽는다. 도구가 있다는 사실만으로 로그인이나 파일 첨부 가능 상태를 확인했다고 쓰지 않는다. 브라우저 제어와 사이트 로그인 상태를 따로 확인한다.
3. 권한 거부·승인 요구를 다른 브라우저로 우회하지 않는다. 작업 중 전환이 필요하면 미저장 본문·첨부·초안과 상신 여부를 먼저 확인한다. 같은 URL이 보여도 다른 브라우저에 로그인·미저장 내용이 공유된다고 가정하지 않는다. 하나의 문서에서 이어가며 중복 기안을 만들지 않는다.
4. 로그인 화면·세션 만료가 보이면 사용자에게 해당 창에서 직접 로그인하도록 알린다. 비밀번호·OTP를 채팅으로 받거나 저장하지 않는다. 실제 사용자와 작성 계정이 맞는지 확인하고 이어간다. 초안 작성·자료 분석만 요청받았다면 브라우저 연결을 요구하지 않는다.

## 실제 확인한 메뉴와 양식

2026-10-23 확인한 경로는 **전자결재 → 결재작성(연필 아이콘) → 협조결재 → 양식구분 인사 → 의료비 지원 신청서**다. 작성 화면 경로는 `/ngw/app/#/approval/write/progress/ireq/`였다. 현재 UI의 이름과 선택 상태로 식별하며 이 URL만 열었다고 의료비 양식이 선택됐다고 가정하지 않는다.

- 분류를 바꾸면 양식 목록·본문·기본 수신자가 늦게 바뀔 수 있다. 로딩이 끝난 뒤 선택 양식, 제목, 본문 인적 사항·금액표, HR 수신자를 다시 읽는다. 이전 양식의 수신자를 의료비에 사용하지 않는다.
- 자동 저장 파일 알림이 나타나면 기존 파일을 복구·삭제하지 않는다. 새 작업에 필요한 양식으로 진행하되 진행 중인 동일 신청이 있는지 먼저 확인한다. 기존 문서 수정은 해당 요청이 있을 때만 한다.
- 본문은 편집기 iframe 안의 표였고 본인/가족 체크박스가 있었다. 현재 DOM·접근성 상태에서 실제 칸과 입력 위치를 확인한다. 빈 표 셀은 텍스트 필드로 표시되지 않을 수 있다. 지원되는 UI 입력으로 편집하고 표의 라벨·주의사항·HR 공란을 보존한다. 내부 앱 상태를 덮어쓰거나 다른 신청서 본문 전체로 교체하지 않는다.
- 소속·사번·직위·성명은 본문에도 기입할 칸이 있다. 결재 머리말에 자동 표시됐다는 이유로 본문까지 채워졌다고 판단하지 않는다.
- 제목은 양식 선택으로 자동 표시된 **의료비 지원 신청서** 그대로 유지한다. 본문에 넣을 이름·테스트 표시를 제목에 덧붙이지 않는다. 현재 제목을 확인하는 동작과 제목을 편집하는 동작을 구분한다.

사용자가 회수한 문서의 체크·내용 보완을 요청하면 공식 수정 경로를 확인한다. 조회 전용 원문을 우회해 수정하지 않는다. 공식 재기안으로 보완할 때는 같은 원문에서 미상신 작성 상태로 전환하고, 기존 결재선·참조자/열람자·첨부의 유지 여부를 확인한다. 기존 대상이 같고 공유 범위를 넓히지 않는 유지 선택이 명확하면 그대로 진행하며, 유지할지 전부 비울지 다시 질문하지 않는다. 실제로 새 대상이나 불명확한 변경 범위가 나타난 경우 그 부분만 확인한다. 원문의 회수 상태와 새 작성 상태를 구분해 보고하며, 재상신은 별도 실행 범위다. 첨부 확인을 위해 임의로 상신·회수하지 않는다.

## 셀 입력과 검증

이 편집기는 iframe 안의 표다. 바깥 페이지와 편집기 안쪽에 각각 스크롤이 있으며, iframe의 값을 읽는 도구 호출도 바깥 페이지를 이동시킬 수 있다. 읽기 전 화면의 좌표는 다음 입력 위치의 근거가 되지 않는다.

1. 현재 URL·선택 양식·기본 제목과 기존 입력을 읽고 같은 초안에서 이어간다. 양식 로딩이나 자동 복구로 본문이 바뀌었으면 입력을 중단하고 현재 양식을 먼저 확인한다.
2. 대상 칸을 **행 라벨 + 병원/약국 구역**으로 식별한다. 표 전체가 편집 가능해도 라벨·주의사항·HR 칸은 입력 대상이 아니다. 행/셀 번호는 현재 표 구조를 읽어 확인한 뒤에만 보조로 사용한다.
3. 실제 셀을 안정적으로 지정할 수 있는 지원 UI 입력을 사용한다. 셀 locator 클릭·fill이 다른 메뉴를 누르거나 효과가 없으면 반복하지 않는다. 좌표 클릭 자체도 스크롤을 바꿀 수 있으므로, **클릭 → 선택된 칸 관찰 → 한 값 입력**으로 나눈다. 현재 라벨에 해당하는 칸의 선택/포커스가 확인되지 않으면 입력하지 않는다. 여러 셀을 Tab 횟수나 과거 좌표로 찾아가지 않는다. 짧은 값에 문단 붙여넣기를 쓰면 행 높이가 늘어날 수 있다.
4. 입력 후 표 값을 다시 읽어 **해당 칸만 예상 값으로 바뀌었는지** 확인한다. 라벨·인접 칸·HR 공란·제목뿐 아니라 행별 셀 수와 병합 구조도 대조한다. 다르면 다음 칸 입력을 멈추고 잘못 바뀐 칸부터 일반 UI로 복구한다. 확인한 수치·문자를 다른 칸에 재입력해 오류를 덮지 않는다. 복구를 검증하지 못하면 저장·상신을 보류하고 변경된 부분만 사용자에게 알린다.
   - 원본이나 변경 전 기록으로 정상값이 확인된 칸은 **그 정상값까지 되돌려야 복구 완료**다. 오류 문자를 지워 빈칸으로 만든 상태는 복구가 아니며 다음 입력으로 넘어가지 않는다. 포커스를 확인할 수 없으면 정상값도 무작정 입력하지 않고 해당 칸의 복구를 보류한다.
5. 값을 읽은 뒤에는 최신 화면을 다시 관찰해 다음 칸의 위치를 정한다. 스크롤·창 크기·편집기 확대·행 높이·다이얼로그가 바뀌면 이전 좌표를 폐기한다. DOM의 viewport 좌표와 스크린샷 픽셀은 DPI·표시 배율에 따라 다를 수 있으므로 같은 좌표라고 단정하지 않는다. 같은 높이일 것이라는 가정으로 좌표 입력을 연속 실행하지 않는다.
6. 양식은 일반 작성 화면에서 편집한다. 입력 실패를 이유로 소스코드/HTML 편집 창·개발자 도구를 열거나 스크립트·내부 앱 상태로 본문을 교체하지 않는다. 일정 등 다른 업무 메뉴로 이동했다면 추가 입력을 멈추고 같은 초안의 보존 상태부터 확인한다.

사용자가 필수값·가독성에 영향 없는 빈 열 등 외형 차이를 그대로 두라고 명시하면, 그 상태를 해당 초안의 검증 기준으로 기록하고 삭제나 수동 정리 요청을 멈춘다. 해당 지시를 반영한 상태에서 대상·금액·라벨·결재선·공개 범위와 HR 공란을 검증해 마무리한다.

- 기존 값·신청일을 교체할 때는 해당 값의 선택 범위를 화면에서 확인한 뒤 입력한다. 여러 문단이 있는 셀에서 Home/End 조합과 입력을 한꺼번에 실행하지 않는다. 표 전체 선택이나 안내 문구 삭제가 감지되면 지원되는 실행 취소로 복구하고 표 원문을 대조한다.
- 본인/가족 체크박스는 현재 iframe에서 정확히 식별하고 **먼저 선택 상태를 읽는다.** 이번 양식은 iframe 클릭/`check()`가 빗나갈 수 있으므로, 상태를 바꿔야 할 때 지원되는 해당 체크박스 locator의 `press('Space')`로 직접 포커스·키보드 선택을 수행한다. 본인 신청은 **본인 true / 가족 false**, 가족 신청은 반대인지 실제 상태와 선택 표시를 확인한다. 이미 맞는 값에 Space를 다시 눌러 해제하지 않는다. 편집기 재생성·복구·재기안 후에도 선택과 표 구조를 다시 검증한다.
- 접근성 요소 번호는 해당 관찰 결과에서만 사용한다. 스크린샷 관찰이나 재렌더링 뒤에는 예전 번호를 재사용하지 않고 현재 접근성 트리에서 다시 찾는다.

브라우저의 주소 확인 실패나 제어 중단은 셀 입력 오류와 별개로 보고한다. 안전상 제어가 중단되면 다른 브라우저·네이티브 창 제어로 우회하지 않는다. 중단 시점의 입력 완료 항목과 잘못 입력된 칸, 첨부·저장·상신 여부를 구분해 남긴다.

## 결재선 설정

1. **사용자에게 이번 건 상급 결재자와 본인 직책을 확인한 뒤** `결재선`의 조직도 버튼을 연다. 조직도 검색에서 성명·소속·직위/직책을 대조하고 동명이인 또는 조직 불일치만 질문한다.
2. 검색 결과에서 선택한 뒤 **선택 목록의 +**로 추가한다. 체크만 했다고 추가됐다고 판단하지 않는다. 선택 목록에 들어간 것을 확인하고 위·아래 이동으로 **기안자 → 확인받은 상급 결재자 → HR 수신부서** 순서를 맞춘다.
3. 각 사람을 선택해 `결재방법`을 확인한다. 현재 UI에는 내부결재·합의부서(필수/선택)·수신부서가 있었다. 의료비 양식의 이충훈 계정은 **HR파트 / 대리 / 수신부서**로 기본 표시됐다. 안내의 HR팀·DL 표기와 실제 조직 표시는 구분하며, 현재 양식/조직에서 동일 담당자인지 확인한다. 상급자는 승인/전결 경로에 두고 HR 수신을 그 앞에 두지 않는다.
4. 독립센터장 예외는 안내와 사용자 답변에 따라 직접 전결 역할을 확인한다. 수신부서로만 둔 것을 직접 전결로 처리했다고 보고하지 않는다. 해당 전결 설정이 확인되지 않으면 결재선만 미확정으로 남긴다.
5. 결재선 창의 `저장`은 문서 상신과 구분한다. 창을 닫은 뒤 본문 위 결재선에도 인원·순서·역할이 반영됐는지 확인한다. 개인 결재선을 새 기본값으로 저장하는 것은 별도 요청이 있을 때만 한다.

## 파일 첨부

양식의 **첨부파일 → PC → 파일추가**를 사용한다. `오피스 파일 읽어오기`는 증빙 첨부와 다른 기능이다. 확인 당시 업로더에 합계 1500mb가 표시됐으나 확장자·개별 제한·현재 한도는 실행 화면에서 확인한다.

- 원본을 대조해 준비한 병원용·약국용 파일만 첨부한다. 브라우저 도구의 현재 파일 업로드 지침을 따르고 필요한 권한이 없으면 그 조치만 요청한다. 보안 설정을 임의로 낮추지 않는다.
- **준비한 파일이 실제 첨부 목록에 표시되고 오류가 없으면 첨부 완료다.** 파일명·개수를 대조하고, 크기는 표시되는 경우 확인한다. 이 그룹웨어의 **전송률 0%는 정상 표시**이므로 100% 대기·재첨부·추가 전송을 하지 않는다. 누락·오류가 있는 파일만 보완하고 정상 등록된 파일은 유지한다.
- **미상신 작성 테스트**에서도 목록 정상 등록을 확인하면 `입력 검증 완료·미상신 / PDF 2개 첨부 완료`로 보고한다. 0%만으로 대기·미완료·서버 저장 미확인으로 분류하지 않으며, 첨부 확인을 위해 상신하거나 100%가 될 때까지 기다리지 않는다.
- 원본 파일, 임시 결합 PDF, 환자 정보는 공유 스킬이나 배포 ZIP에 넣지 않는다. 사용자가 준 영수증을 제3자 서비스·불필요한 참조자에게 전송하지 않는다.

## 상신과 완료 확인

확정 입력값·결재선·첨부를 실제 화면에서 검토하고 사용자 요청의 실행 범위에 맞춰 **결재상신**을 한 번 실행한다. 그다음 추가되는 공개/열람·메일·상신의견 등 설정은 현재 화면에서 확인한다. 새로운 공유 범위나 민감정보 전송에 필요한 승인이 부족하면 해당 내용을 준비한 뒤 확인받는다. 이미 확인한 동일 내용의 실행 허락은 반복해서 묻지 않는다.

상신 이후 문서 상세 또는 결재진행 내역을 읽어 **문서번호, 신청자·수진자, 금액표, HR 전용 공란, 전결자·HR 수신 역할, 저장된 첨부, 현재 상태**를 대조한다. 실제로 확인하지 못한 결과를 상신 완료로 보고하지 않는다. 응답 지연·오류 시 기존 문서 상태와 첨부를 먼저 조회하고 중복 상신을 막는다.

관찰·작성·첨부·상신 권한은 구분한다. 작성 테스트에서는 사용자가 지정한 자료와 시험 가정을 본문에 명시하고 실제 상신 없이 입력 결과를 확인한다. 실제 건의 접수와 승인·급여 지급은 각각 별도로 확인한다. 개별 테스트의 성명·사번·영수증·화면 캡처는 재사용 스킬과 배포 ZIP에 넣지 않는다.
