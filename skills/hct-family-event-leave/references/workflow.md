# 사내 근태 공통 작업 절차

이 파일은 해당 스킬 폴더에 포함된 실행 지침이다. 다른 근태 스킬을 함께 설치할 필요가 없다. 화면 확인 기준은 2026-10-15이다. 현재 화면과 다르면 현재 화면을 다시 확인한다.

## 요청 범위와 입력정보

- 설명·검토·초안 요청이면 그 범위까지만 수행한다. 실제 신청·취소까지 요청받았다면 필요한 정보를 갖춘 뒤 해당 작업을 진행한다. 같은 세션에서 받은 정보와 작업 승인을 다시 묻지 않는다.
- 사용자에게 필요한 결과, 실제 신청자, 날짜·시간대, 사유 중 빠진 정보만 묻는다. 신청자는 현재 로그인 계정과 양식의 자동 표시값을 대조하며, 이전 사용자의 이름·사번·부서·결재선을 가져오지 않는다. 이미 확인한 값은 재사용한다.
- 상대 날짜는 사용자 시간대(기본 Asia/Seoul)의 실제 실행일을 기준으로 절대 날짜로 정리한다. 모호한 오전·오후, 종료일, 자정을 넘는 시간은 추측하지 않는다.
- 신청사유는 실제 사용자가 제공한 내용으로 작성한다. 회사가 요구하는 증빙이 있을 때만 해당 증빙을 준비하며, 없는 사실·서류를 만들지 않는다. 불필요한 의료·가족 세부정보는 요구하지 않는다.
- 화면 선택지의 존재는 대상 자격·인정 기간·유급 여부·사용 가능 잔액의 증거가 아니다. 해당 신청에 필요한 미확인 회사 기준만 확인한다.

## 브라우저 선택

- 실제 브라우저 작업이 필요할 때만 Aside의 설치·도구 존재를 확인한다. 사용자가 브라우저나 특정 탭을 명시하면 그 선택을 우선하며, 읽어 달라고 지정한 사이드패널 탭도 사용할 수 있다.
- 별도 지정이 없고 Aside 도구나 CLI가 있으면 현재 Aside 지침(`aside-browser` 스킬, CLI 사용 시 `aside guide`)을 먼저 읽고 연결·탭 상태를 확인한다. 사용 가능하면 Aside를 사용한다. 미설치·비실행·연결 불가 등으로 Aside를 사용할 수 없으면 설치를 요구하지 않고 Chrome으로 진행한다.
- 도구 권한 거부는 Chrome 등 다른 브라우저로 전환해 우회하지 않는다. 도구의 승인·보안 요구를 따른다.
- 브라우저 전환 전 미저장 입력·첨부와 기존 신청의 접수 여부를 확인한다. 상태가 불명확하면 보존·조회부터 하고, 전환을 이유로 신청을 다시 생성하지 않는다. 브라우저 선택은 신청·취소 등 업무 권한을 추가하지 않는다.

## 접속과 메뉴

1. 선택한 브라우저 도구의 지침을 읽고 기존 사내 ERP 업무 탭을 재사용한다. 없으면 선택한 브라우저에 [사내 ERP](https://erp.hcterp.com/) 새 업무 탭을 연다. Chrome을 선택한 경우에도 기존 Chrome 업무 탭을 먼저 찾는다.
2. 실제로 로그인 사용자와 메뉴 접근 가능 여부를 확인한다. 로그인 화면·세션 만료가 보이면 사용자에게 해당 ERP 창에서 로그인해 달라고 알리고 기다린다. 비밀번호를 채팅으로 요청하거나 저장하지 않는다. 도구 연결 문제가 있으면 로그인 문제와 구분해 알린다.
3. **인사관리 → 대사우관리(ESS) → 근태신청관리 → 근태신청(HCT)**로 이동한다. 마지막 메뉴까지 선택한다. 확인된 화면 경로는 `/HR/PAMAAH00100_X20567`이다.
4. 각 스킬이 지정한 상단 신청항목 행의 **신청**을 눌러 양식을 연다. 이 버튼은 양식 열기다. **양식 하단의 신청은 실제 제출**이다. 하단의 근태·근무 탭과 신청구분 필터는 내역 조회용이다.

## 화면 조작과 제출

- 새로 연 양식의 신청자·종류·구분·날짜를 모두 확인한다. 이전에 선택한 값이 남아 있을 수 있으므로 초기값을 그대로 믿지 않는다.
- 메뉴 목록은 캔버스로 표시되어 DOM 텍스트에 없을 수 있다. 해당 경우 현재 스크린샷에서 행 이름과 버튼 위치를 확인한다. 과거 좌표·탭 ID를 고정하지 않는다.
- 드롭다운을 연 다음 현재 선택 목록을 읽고 선택한다. 연속 클릭 직후 화면 갱신이 덜 되었으면 새 상태로 확인한다. 옵션의 단축번호를 저장하지 않는다. Escape는 양식 전체를 닫을 수 있으므로 목록 닫기 용도로 무작정 쓰지 않는다.
- 날짜·종류를 바꾼 뒤 계산된 일수·시간, 종료일 잠금, 식사 선택 상태를 다시 읽는다. 비활성 필드나 자동 계산을 스크립트로 덮어쓰지 않는다. 주말·공휴일·근무조에 따른 일수와 시간은 화면 계산 및 적용 기준을 대조한다.
- 동일 날짜·종류의 기존 신청과 처리 상태를 확인한다. 확인이 필요하면 아래 조회 절차를 사용한다. 취소나 삭제가 별도로 요청되지 않았다면 기존 신청을 임의로 바꾸지 않는다.
- 제출 전 신청자, 신청종류·구분, 절대 날짜·시간, 일수/시간, 사유, 필요한 증빙을 짧게 정리하고 실제 입력값과 대조한다. 사용자가 이미 요청한 제출 범위와 일치하면 진행하며, 핵심 입력값·자격 기준이 미확정이면 그 부분만 확인한다.
- 최종 신청은 한 번 실행한 뒤 결과를 확인한다. 응답 지연·오류로 접수 여부가 불명확하면 먼저 내역을 조회한다. 확인 없이 다시 눌러 중복 접수하지 않는다. 여러 건 신청은 건별로 접수 여부를 기록한다.

## 신청내역 조회와 완료 판정

1. **근태** 탭은 신청구분 `근태신청` 또는 `근태신청취소`를 선택한다. **근무** 탭은 `시차출퇴근 근무 신청`, `시프트 근무 신청`, `야간 근태신청`, `잔업신청`, `휴일근무신청` 중 맞는 항목을 선택한다.
2. **신청일은 제출한 날짜**다. 사용일이나 근무일과 구분한다. 지난달에 신청한 다음달 휴가라면 먼저 지난달이 포함되도록 신청일 범위를 지정한다. 신청 시점이 불명확하면 관련 기간으로 단계적으로 넓힌다.
3. 결재상태는 찾는 상태로 맞춘다. 상태를 모르면 빈 값(미지정)으로 두어 특정 상태 때문에 제외되지 않게 한다. 화면에는 신청·미결·승인·반려·승인취소·임시저장·신청회수·담당회수·담당확인 등이 있다.
4. 조건을 정한 뒤 **상단 조회 버튼 또는 F2**를 실행한다. 필터 변경이나 탭 전환만으로 조회 완료라고 판단하지 않는다.
5. 결과의 신청번호·신청구분·휴가구분, 시작일·종료일, 일수/시간, 결재상태 중 제공되는 항목을 원 요청과 대조한다. 결과가 비었으면 신청일·탭·신청구분·결재상태 조건부터 점검한다. 없다는 이유로 새 신청을 만들지 않는다.
6. 양식 열기, 근무조 적용, 창 닫기는 접수 완료의 증거가 아니다. `초안`, `접수 확인`, `승인 완료`, `접수 여부 확인 필요`를 실제 결과에 맞게 구분한다. 접수와 승인을 같은 뜻으로 쓰지 않는다.

완료 보고에는 처리한 종류와 날짜, 실제 확인한 일수/시간, 신청번호·상태(확인된 경우), 남은 확인사항만 적는다. 실제 계정정보·신청내역은 해당 작업 기록에서만 사용하고 재사용 스킬 파일에 기록하지 않는다.

작성한 본문과 결과 문구를 해당 건의 요청·증빙과 대조해 다른 건의 날짜·사유·문장이 섞이지 않았는지 확인한다. 여러 건을 함께 처리하면 건별 입력값·근거·현재 상태를 분리한다.

## 근거의 범위

- 메뉴·양식·선택지와 일부 자동 계산: 2026-10-15 실제 ERP 화면 확인.
- 0.75일을 0.25일+0.5일 두 건으로 신청, 먼저간DAY 월 1회·금요일만·같은 날 다른 연차와 중복 불가: 2026-10-15 사용자 확인 운영 규칙. 별도 사규 원문을 검증한 것은 아니다.
- 실제 제출·승인 후 반영, 취소 후 잔액 복구, 주말·공휴일 포함 계산의 모든 경우는 사전 시험하지 않았다. 실제 작업의 결과를 별도로 검증한다.
