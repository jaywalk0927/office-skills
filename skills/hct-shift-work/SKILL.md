# 사내 시프트 근무

하루 단위 출퇴근 시간 조정을 위한 시프트 신청을 작성·확인한다. 화면 정보는 2026-10-15에 확인했다.

실제 브라우저 작업 전 [작업 절차](references/workflow.md)를 반드시 읽고 따른다.

## 화면과 입력

- 상단 **시프트 근무 신청**을 열면 양식 제목은 **시프트근무신청**이다.
- 근무일, 희망 시작·종료 시각, 식사 여부와 신청 사유를 확인한다.
- **1일 단위** 신청이며 시간은 **30분 단위**로 선택한다. 시작 가능 시각은 **07:30부터**이고 **08:00~17:00은 신청 불가**다.
- **1주 이상**의 조정은 시차출퇴근 신청 절차 적용 여부를 검토한다.
- 독립된 **야간 근태신청 → 야간근무신청**과 이 양식의 야간 시프트를 혼동하지 않는다.

## 시간·식사 확인

날짜가 비어 있던 양식에서 다음 반응을 확인했다. 실제 날짜와 식사 선택에 적용되는 확정 규칙으로 확대하지 않는다.

| 시작 시각 선택 | 당시 종료 시각 | 당시 식사 상태 |
|---|---|---|
| 07:30 | 16:30 | 조식 선택 활성화 |
| 10:00 | 19:00 | 석식 선택 활성화 |

- 식사 선택은 화면 상태를 바꾼다. 실제 근무일과 식사 여부를 입력한 뒤 종료 시각·식사 항목·안내를 다시 읽는다.
- 위 표의 종료 시각이나 식사 라벨을 모든 신청에 고정하지 않는다. 표시 결과가 희망 조건과 맞는지 확인한다.

## 야간 안내 충돌

- 목록 안내는 **20:00~06:00**, 양식 안내는 **22:00~06:00**으로 서로 다르다.
- 양식에는 야간 시프트에 **별도 전자결재 및 그룹장 승인**이 필요하다고 표시된다.
- 요청이 **20:00~22:00**에 걸치거나 야간 해당 여부가 불명확하면 적용 사내 기준과 결재 요건을 확인한 뒤 해당 신청을 진행한다. 사용자가 기준을 모르면 인사 담당자 또는 공식 정책의 확인이 필요함을 알린다.
- 어느 안내가 우선인지, 법적 야간 기준과 같은 의미인지 추정하지 않는다. 이 충돌만으로 일반 주간 시프트까지 중단하지 않는다.
- 처리 후 **근무** 탭에서 **신청구분: 시프트 근무 신청**과 근무일을 대조해 내역·상태를 확인한다.

## 사용 예

사용자: “$hct-shift-work 이번 금요일에 10시 시작으로 시프트 신청하려고 해.”

이번 금요일의 실제 날짜, 희망 종료 시각과 식사 여부·사유를 확인한다. 양식에서 10:00 선택 후 현재 표시되는 종료 시각과 식사 항목을 읽어 신청 내용을 검토한다. 빈 날짜 양식의 19:00 표시만으로 종료를 확정하지 않는다.
